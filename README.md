## 2. 系统技术架构与核心程序说明

系统经过精炼重构，核心爬虫业务代码仅保留 4 个高内聚模块，彻底删除了不执行现有爬虫进程的废弃文件：

| 核心文件 | 定位与核心职责 |
|---|---|
| **`crawler/main.py`** | **统一调度主入口**：面向用户的统一命令行主程序，支持单媒体、分类、全网全量一键调度。 |
| **`crawler/unified_crawler.py`** | **多源统一爬虫引擎**：整合通用新闻、政务公文要素提取、融媒文稿清洗与自适应编码转换（UTF-8/GBK/GB18030）。 |
| **`crawler/domain_mapper.py`** | **权威域名与融合平台映射中心**：集中维护政务、地方大报、部委重点刊物及县级融媒体的公网真实合法域名，根治中文假域名。 |
| **`crawler/sites_registry.py`** | **媒体配置与注册中心**：基于底表与映射库，动态为全量 1217 家媒体生成规范化抓取配置字典。 |
| **`crawler/all_media_manifest.json`** | **官方媒体档案库**：经过实测验证的 1217 家高可用合规媒体档案元数据。 |
| **`crawler/data/`** | **数据分层存储目录**：按类别和媒体名称结构化落盘 `.jsonl` 数据。 |

### 5.6 立即启动、有限循环与异常重试（2.3 版）

在项目根目录、原爬虫虚拟环境中执行：

```bash
python daily_crawler.py --check
python daily_crawler.py
```

第一条只检查配置，不采集；第二条立即启动，不再等待零点。
每轮正常结束后立即开始下一轮，默认完成 50 轮后调度器退出。
文件顶部 `LOOP_COUNT = 50` 控制正常完成的轮数；异常退出不消耗轮数。
发现子进程非零退出（包括 OOM 后的 -9）后立即重启当前轮，检测间隔为
`POLL_SECONDS = 1` 秒；没有额外重试等待或重试次数上限。
长期无法恢复的故障会持续重试，自动重试并不能解决内存不足。

所有原命令行参数仍在顶部设置：

| 常量 | 对应参数 | 当前值 |
|---|---|---|
| `NAME` | `--name` | `""` |
| `CATEGORY` | `--category` | `""` |
| `ALL` | `--all` | `True` |
| `MAX_ARTICLES` | `--max-articles` | `20` |
| `WORKERS` | `--workers` | `2` |
| `LIMIT` | `--limit` | `0` |
| `LIST_SITES` | `--list-sites` | `False` |

`NAME`、`CATEGORY`、`ALL` 三选一；`LIST_SITES=True` 时每轮只打印名单。
每轮从 `crawler/all_media_manifest.json` 重新构建媒体注册表。
每家每次进程最多采集 20 篇，不保证一定取得该数量；重试时该数量重新计算。

成功 URL 断点沿用 `crawler/data/visited_urls.txt`，另有 5.7 节所述持久任务记录：新进程重新遍历媒体与频道，
跳过已记录成功的文章 URL，未完成的 URL 可以再次尝试。
这是已保存 URL 和已开始任务的恢复，不是精确媒体游标或内存解析现场恢复；全局去重记录跨轮保留。
在文章已写入但去重记录未写入时被强制终止，仍可能重复，两个文件没有事务保证。
原爬虫捕获并记录的单站异常不会使整个进程失败，也不会触发整轮重启。
调度器自身被杀死或服务器重启不会自行恢复，需外部服务管理器或手动启动。
每次重启调度器，50 轮的计数重新开始；修改常量也需要重启调度器。

日志仍为 `scheduler_logs/scheduler.log`、各次尝试的 `crawl_日期_时间.log`，
以及 `crawler/crawler.log`。时区常量仅用于每次尝试的日志文件名。
Ctrl+C / SIGTERM 停止后续调度，已启动的爬虫继续执行。
同一项目的进程锁阻止重复调度器和重叠采集；旧爬虫仍运行时，新调度器等待运行锁。
不要删除锁文件，也不要同时手动运行 `crawler/main.py` 向同一目录写入。

离线测试（临时假入口，不访问网站）：

```bash
python -m unittest -v test_daily_crawler.py
```

### 5.7 完整内容与内存修复（2.3）

源码目录与文件名保持原样，无新增源码模块。默认 2 个线程；内存较小的服务器
先临时设置 `LOOP_COUNT=1` 做完整一轮观察，再决定是否恢复 50 轮。

- 下载使用 `stream=True`，按 64 KiB 分块写入现有 `crawler/data` 下的
  `page-*.download`。分块大小不是页面上限，没有正文长度截断。
- 完整下载后，逐块严格验证编码，再逐块解码喂给 lxml / BeautifulSoup。
  不再同时保留完整响应 bytes 和完整 HTML 字符串。支持 UTF-8、GB18030 等原有编码；
  无法无损解码时明确失败并保留下载，不用替换字符冒充完整正文。
- 为保持现有 CSS 选择器，仍会构建完整解析树。使用 lxml 的 target 接口连接 BS4 builder；
  升级依赖后必须重跑测试。对任意大的树仍可能 OOM，不能承诺 1.8 GiB 内存足够。
  未启用 DOM 节点数量、响应字节数或正文字符数的截断。
- 每个正文文本节点按顺序访问一次，不再重复拼接嵌套 div/p。保留直接写在 div 的文本、
  短段落、段落顺序和原文重复句；空白标准化，块元素间换行。已有 script/style/nav 等
  非正文过滤和标题/正文有效性判断仍存在，因此这是正文提取，不是原始 HTML 的逐字复制。
- 频道链接提取后立即释放频道树，文章提取后先释放文章树再保存；异常分支也清理。
  每个频道结束执行垃圾回收，JSON 直接写文件，减少完整 JSON 字符串副本。
- 日志记录 URL、阶段、完整下载字节数和 Linux `VmRSS`/`VmHWM`（当前/峰值驻留内存）。
  Windows 日志明确显示 RSS unavailable；不把 Python 对象统计冒充进程内存。

运行时会在现有 `data` 中生成 `crawl_tasks.sqlite3`（任务状态数据库），不是采集数据替代品。
任务包含媒体、频道、URL、下载路径、下载完成标记、阶段、失败原因和计数。
成功完成后删除该任务的下载缓存；失败/中断时保留供恢复或检查，注意磁盘空间。
进程重启将遗留 running 标记为 interrupted/pending（数据库状态为 pending，原因中说明中断）；
完整下载可直接复用，不必重新请求。即使频道重新请求失败，也会处理该频道已记录的 pending 文章。

`crawler/unified_crawler.py` 顶部 `MAX_TASK_FAILURES=2` 控制连续失败次数。
到达阈值的任务变为 `deferred`（待处理），后续自动遍历不再反复处理它，
但不会写入 visited、不会伪装成功，也不会删除已完整下载的页面。
OOM 杀死整个进程时，两个线程的在途任务都会被记录为中断；不能据此断言它们都导致了 OOM。
待处理任务需人工检查或转到大内存环境重试。这避免无限撞到同一页面，并不意味着数据已采全。
单轮进程正常退出仍只代表遍历结束；应同时检查状态汇总，pending/deferred 非零表示有未完成任务。

在项目根目录，用原虚拟环境执行：

```bash
python daily_crawler.py --task-status
```

该命令只读任务状态，不启动采集。输出未完成 URL、阶段、错误及下载路径。
停止调度器和工作进程后，可单独重置某个 URL：

```bash
python daily_crawler.py --retry-task 'https://实际待处理文章地址'
```

这只重置任务失败计数和状态；下次运行且包含其媒体/频道时重试。
不要清空 visited 或手改、删除数据库和下载文件。该数据库不记录本版部署前的失败请求。
文章和 visited 仍是两个文件，突然断电/强制终止时仍存在跨文件不一致窗口，不能保证恰好一次保存。

部署本版要更新 `crawler/unified_crawler.py`、`daily_crawler.py`、
`test_daily_crawler.py`、README，保留服务器数据目录。仅替换启动器无法启用内存修复。
部署后先运行离线测试，再小规模实测并观察内存；本地测试不是服务器真实站点压测。

### 5.8 网页子进程隔离与内存阈值

`WORKERS=N` 表示最多 N 个媒体工作线程，每个线程同时只管理一个网页子进程。
因此最多 N 个网页子进程同时工作，不是每个线程再创建 N 个进程。
运行结构为启动器 → 主爬虫进程（N 个工作线程）→ 最多 N 个网页子进程。
频道页下载/提取文章 URL、文章页下载/正文解析都在网页子进程中执行，
每个页面处理完就退出。主爬虫负责去重、任务记录、进程监控和最终文章写入。

在 `crawler/unified_crawler.py` 顶部设置：

```python
PAGE_MEMORY_LIMIT_MIB = 100
PAGE_MEMORY_POLL_SECONDS = 0.1
```

这里的 100 MiB 是单个网页子进程总驻留内存（包含 Python/解析库），不是网页文件大小，
也不是相对基线增加量。Linux 读取 `/proc/PID/status`，Windows 使用系统进程内存接口，
检查当前值及峰值。它是约 0.1 秒间隔的采样保护，不是硬配额；瞬时增长可能超出阈值。
子进程自身也检查内存和父进程存活情况，但整个机器断电、系统先触发 OOM 等仍不能保证恢复。

超限时终止并回收当前网页子进程；该 URL 立即标为 deferred / memory_limit，
保留任务和已有下载，不更新 visited。工作线程继续处理下一篇文章；频道页超限时，
仍可处理此前记录的 pending 文章，新的候选链接需要该频道恢复成功后才能获得。
只接受成功退出子进程的完整结果；部分 IPC 输出不进入文章 JSONL。
结果通过 `data/page-ipc-*.json` 临时文件传递，正常回收后删除；强制终止父进程可能留有临时文件。

100 MiB 可能不足以处理某些正常复杂网页，应通过 `--task-status` 检查待处理任务，
调整阈值或改用更大内存环境后通过 `--retry-task URL` 恢复。不要把 deferred 当成数据采集成功。
每个进程有基础开销，频繁启动会增加耗时；目前启动器仍保持 2 线程，不能据此推断 8 线程在小内存服务器安全。
网页子进程受限不等于父进程内存受限；父进程的去重集合和完整结果也占用内存。

查看全部相关进程（原先只匹配 daily_crawler.py 的命令看不到网页子进程）：

```bash
ps -eo pid,ppid,etime,rss,args | grep -E '[p]ython.*(daily_crawler\.py|unified_crawler\.py)'
```

带 `--page-worker` 的进程是网页子进程。升级后要停止旧采集进程、上传修改后的
`crawler/unified_crawler.py`、测试文件和 README，在服务器运行离线测试后再小规模试跑。

## 6. 运行监控、数据统计与断点防重续爬

### 6.1 实时统计已入库文章数量
你可以随时在终端运行以下命令，统计当前各大分类已抓取的文章总数与文件数：

```bash
# 统计全库目前抓取的文章总篇数
find crawler/data -name "*.jsonl" | xargs wc -l

# 查看各分类分别入库的媒体数量与目录结构
find crawler/data -type d -depth 2
```

### 6.2 断点续爬与防重保证
- 所有成功下载的文章 URL 都会实时追加至 `crawler/data/visited_urls.txt`。
- 无论是中途手动按 `Ctrl + C` 终止，还是机器意外重启，**重新执行任何爬虫命令时，系统会自动读取已访问列表并立即跳过已抓文章**，通常会跳过已记录成功的 URL；文章文件与去重文件之间没有跨文件事务，异常终止时仍可能重复，详见 5.7。

## 7. 常见问题与技术保障机制

| 常见问题 | 原因分析与系统的自动处理方案 |
|---|---|
| **为什么收录媒体数是 1217 家？** | 原 1432 媒体名单中包含 200 余家客观停运关停（公网无 DNS 解析）、纯手机端单页应用（无 Web 文章）以及政务内网防爬阻断的站点。为了保证生产爬虫的纯度与 100% 成功率，系统将异常站点移出，确保收录的 1217 家均经过全网实测核验，100% 可通可采。 |
| **老旧地方小报或政务网中文乱码** | 许多地方网站使用 `GB2312` 或 `GB18030` 编码。系统内置自适应编码探测矩阵（`utf-8` -> `gb18030` -> `gbk` -> `gb2312`），多轮解码校验 `\ufffd` 替换符，确保正文 100% 正常显示。 |
| **政府网站的公文包含附件和表格** | 政务公文很多内嵌表格与条款序号。统一抽取引擎对段落进行自适应保留，自动提取发文字号和成文日期，并清洗页脚噪点。 |
| **广播电视台只有视频没有大段文字** | 抽取器剥离了 `<video>` 和播放插件，优先提取主持人播报文稿、新闻导语，如果文字少于 40 字则予以剔除，确保语料的高纯度。 |
| **如何停止后台运行的爬虫进程？** | 执行 `pkill -f main.py` 即可优雅终止。已抓取的所有数据和 URL 会完整安全保存在本地。 |
